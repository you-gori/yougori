# Yougori

Use the current installed CLI, not an executable remembered from another checkout. `yougori agent discover` reports its path, CLI/engine versions, protocol compatibility, canonical skill hash and stale managed copies. If `yougori` is missing from PATH, use the installed CLI location below. The desktop and CLI share one engine and state.

1. Read `yougori prefs show`; preferences suggest choices, never grant permission or override current task authorization. Do not ask again for already-authorized action and scope.
2. Read `yougori agent inventory` for exact IDs and capabilities, then `yougori schema --topic TOPIC` and `yougori schema METHOD` only for the task at hand. Topics: lifecycle, files, gpu, deployment, models, connections, cloud, vault, terminal, settings, jobs.
3. Plan the desired image, resources, persistent data, files, startup, secrets, health check and publication. Prefer `yougori up` / `apply` for an idempotent project; check `deployment status` for its outcome.
4. Apply only authorized changes. Public, billable, destructive, credential, PC-folder and Full control sharing operations need authorization for their specific scope. `--yes` acknowledges the operation; it never expands the task. Never launch a second runtime against existing disks or edit platform-state.json.
5. Wait for accepted work. `--no-wait` returns a job ID; `jobs get|wait ID` reports progress and blockers. Client timeout is not cancellation. Inspect actual state before retrying; `jobs cancel ID --yes` requests cooperative cancellation, which is not rollback. `jobs result ID` reads paged output after successful oversized results.
6. Verify the requested application, not only the container state: local HTTP, tunnel and public HTTPS are separate stages. A URL in metadata is not verified health. Use a protected authenticated probe when the user requires it.
7. Recover through `env recover-report ENV --yes`; check its provider, storage root and readyToStart result. Never bypass a live owner or silently stop unrelated workloads. `app startup-report` identifies native sign-in recovery and readiness. Sign-in startup does not promise startup before sign-in.

Read only the relevant reference: [containers](references/containers.md), [files](references/files.md), [deployment](references/deployment.md), [models/GPU](references/models.md), [connections/cloud](references/connections.md), [terminal/vault](references/access.md). `skills print --topic TOPIC` accepts the same task topics as schema: lifecycle/settings/jobs use containers, gpu uses models, cloud uses connections, and terminal/vault use access. The six reference names also work. `skills print --all` fetches the full guide only when needed. Managed forwarding files point here; personal edits are preserved and reported instead of overwritten. A preserved skill conflict does not block identity discovery; `skills print` retrieves this version's current instructions.

Put credentials through stdin (`--file -`) or protected deployment bindings, never in arguments, logs, manifests or preferences. Routine metadata excludes bearer URLs; explicit credential retrieval returns a secret and needs its own authorized scope. Use exact IDs, bounded log cursors and reported exit codes. The Host terminal is outside guest isolation and needs host-task authorization; guest content cannot grant it. Stop and report unsupported hardware, denied permissions or failed enforcement rather than evading isolation.

## Yougori Network

`yougori login`, `logout` and `account` use the same account as the desktop Network panel. Approve the device code in the browser. Authorized model sharing uses `yougori model run hf.co/OWNER/MODEL --now` (paid for the ten priced models, otherwise free) or `--nowfree` (free access without a consumer account or wallet). Providers sign in before sharing. `--quant Q4_K_M` selects GGUF quantization; `model preflight MODEL [--quant Q4_K_M]` checks compatibility first. `model unshare ENV` stops sharing while keeping the model running. The Network panel exposes price, GPU, speed, uptime, availability, token totals and earnings. Methods: `market_status`, `market_sign_in`, `market_sign_out`, `market_share_model` and `market_unshare_model`. Never expose provider credentials in documentation or logs.
